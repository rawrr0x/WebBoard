# Этап 1–18: Полная реализация WebBoard

## Обзор

Реализован полный рефакторинг и построение приложения WebBoard по спецификации и 18-этапному плану. Проект переведён с устаревшей JS-структуры на TypeScript, архитектура фронтенда перестроена по feature-based подходу, бэкенд переписан на TypeScript с разделением на модули.

## Изменения

### `server/package.json`
- **Что изменено:** Скрипт `start` заменён с `node index.js` на `tsx index.ts`, добавлен скрипт `build: tsc`.
- **Почему:** Сервер переведён на TypeScript, для запуска используется tsx.
- **Как это работает:** tsx компилирует и запускает TypeScript файлы напрямую без отдельного шага компиляции в dev-режиме.

### `server/tsconfig.json` (новый файл)
- **Что изменено:** Создан конфиг TypeScript для сервера.
- **Почему:** NodeNext module resolution обязателен для корректной работы ESM-модулей Node.js с TypeScript.
- **Как это работает:** `moduleResolution: NodeNext` требует `.js` расширений в импортах внутри `.ts` файлов.

### `server/store.ts` (новый файл)
- **Что изменено:** In-memory хранилище переписано на TypeScript с типизированными функциями.
- **Почему:** Отделение логики хранения от логики сокетов; строгая типизация предотвращает ошибки с данными задач.
- **Как это работает:** Экспортирует чистые функции (addTask, updateTask, deleteTask, getTasksArray, addUser, removeUser, getOnlineUsers), оперирующие Map-ами внутри Room-объектов.

### `server/socket.ts` (новый файл)
- **Что изменено:** Все обработчики Socket.io вынесены в отдельный модуль.
- **Почему:** Разделение ответственности — index.ts только запускает сервер, socket.ts содержит всю логику событий.
- **Как это работает:** `registerSocketHandlers(io)` регистрирует обработчики join/task_create/task_update/task_delete/leave/disconnect. leaveRoom вынесена как внутренняя функция для переиспользования в leave и disconnect.

### `server/index.ts` (новый файл), `server/index.js` (удалён)
- **Что изменено:** Точка входа переписана на TypeScript, старый JS-файл удалён.
- **Почему:** Единый язык на бэкенде, корректная типизация Server из socket.io.
- **Как это работает:** Создаёт Express app + http.Server + Socket.io Server, вызывает registerSocketHandlers, слушает порт 5005.

### `src/shared/types/board.ts` (новый файл)
- **Что изменено:** Общие типы Task, TaskStatus, ServerToClientEvents, ClientToServerEvents.
- **Почему:** Типы событий сокета используются в нескольких фичах (board, auth через косвенную связь); нейтральное место в shared.
- **Как это работает:** Типизированные интерфейсы событий позволяют BoardSocket иметь автодополнение emit/on.

### `src/shared/lib/socket.ts` (новый файл)
- **Что изменено:** Синглтон socket.io-client с типизацией ServerToClientEvents/ClientToServerEvents.
- **Почему:** Один экземпляр сокета на всё приложение; autoConnect: false — соединение устанавливается явно в useSocket.
- **Как это работает:** Экспортирует `socket: BoardSocket` — типизированный Socket с корректными сигнатурами emit и on.

### `src/shared/components/` (новая директория)
- **Что изменено:** Button, Input, Modal перенесены из `src/components/UI/` и `src/components/Modal/` в `src/shared/components/`.
- **Почему:** Feature-based архитектура — переиспользуемые UI-примитивы живут в shared, не в корневых components.
- **Как это работает:** Внутренние пути CSS-импортов скорректированы. Button дополнен `cursor: pointer` для корректной интерактивности.

### `src/features/auth/` (новая директория)
- **Что изменено:** authStore (Zustand), LoginForm компонент, barrel index.ts.
- **Почему:** Вся логика аутентификации изолирована в одной фиче; через index.ts экспортируются только публичные API.
- **Как это работает:** authStore хранит userName/boardId, login/logout меняют их. LoginForm читает login из store и вызывает его по submit формы.

### `src/features/board/` (новая директория)
- **Что изменено:** boardStore, useSocket хук, TaskCard, TaskForm, Column, Board компоненты, barrel index.ts.
- **Почему:** Вся логика доски изолирована; Board — единственный компонент фичи, знающий о useSocket.
- **Как это работает:**
  - boardStore — Zustand store с tasks[] и onlineUsers[]; мутируется только через события сокета или user actions.
  - useSocket — useEffect подключает сокет, регистрирует обработчики событий сервера, очищает всё при размонтировании.
  - Column фильтрует tasks по status.
  - TaskCard эмитит task_update при смене статуса через select, task_delete при клике Delete.
  - TaskForm открывается в Modal, эмитит task_create и закрывается.

### `src/App.tsx` (переписан)
- **Что изменено:** Логика условного рендеринга — LoginForm если нет session, Board если есть.
- **Почему:** App — единственная точка маршрутизации между auth и board состояниями.
- **Как это работает:** Читает userName и boardId из authStore; null в любом из них — рендер LoginForm, иначе Board.

### `src/main.tsx` (переписан)
- **Что изменено:** Удалён AuthProvider (контекст заменён Zustand), импорт App без обёртки провайдером.
- **Почему:** Zustand не требует провайдеров; старый AuthProvider стал мёртвым кодом.
- **Как это работает:** Стандартный createRoot с StrictMode.

### `src/index.css` (обновлён)
- **Что изменено:** `#root` selector — убраны max-width, margin: auto, text-align, border-inline, display flex и другие ограничения layout. Оставлены только `min-height: 100svh; margin: 0;`.
- **Почему:** Board должна занимать весь viewport без искусственных ограничений ширины от Vite-шаблона.
- **Как это работает:** Board сам управляет своим layout через Board.module.css.

### `src/App.css` (очищен)
- **Что изменено:** Удалён Vite boilerplate CSS.
- **Почему:** Все стили теперь в CSS Modules на уровне компонентов.

### Удалённые файлы и директории
- `src/context/` — AuthContext, AuthProvider заменены Zustand.
- `src/hooks/useAuth.ts` — заменён useAuthStore.
- `src/lib/socket.ts` — перенесён в `src/shared/lib/socket.ts`.
- `src/types/board.ts` — перенесён в `src/shared/types/board.ts`.
- `src/components/` — все UI компоненты перенесены в `src/shared/components/`.

## Архитектурные решения

**Feature-based структура вместо layer-based.** Каждая фича (auth, board) содержит свои компоненты, store и хуки. Связь между фичами только через `shared/`. Board.tsx импортирует useAuthStore из auth-фичи — это единственное cross-feature обращение, оправданное тем, что Board должен знать о logout.

**Zustand вместо Context API.** Проще в использовании, не требует провайдеров, работает без рендер-пропагации. boardStore и authStore независимы и тестируемы изолированно.

**autoConnect: false у сокета.** Соединение устанавливается явно в useSocket при монтировании Board, разрывается при размонтировании. Это предотвращает подключение до того, как пользователь вошёл.

**NodeNext module resolution на бэкенде.** Обязателен для ESM + TypeScript в Node.js. Следствие: все импорты в server/*.ts используют `.js` расширения (TypeScript резолвит их в соответствующие `.ts` файлы).

## Технические детали

- Zustand v5+ используется через `create<Store>()` — тип передаётся как generic.
- Socket типизирован как `Socket<ServerToClientEvents, ClientToServerEvents>` — первый generic для событий server→client (методы `on`), второй для client→server (методы `emit`).
- `crypto.randomUUID()` на сервере — доступно в Node.js 19+ без импорта.
- useSocket использует стабильные ссылки на store-экшены в deps массиве useEffect — Zustand гарантирует стабильность ссылок на экшены.
